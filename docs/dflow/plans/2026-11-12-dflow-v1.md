## Design

- D1: The CLI is dependency-free Node ESM under `plugins/dflow/lib/`, entered through `plugins/dflow/bin/dflow`. Tests use `node --test` against temporary git repositories.
- D2: The plan file is the record of task state. `.dflow/state.json` holds only what cannot be derived: the task in progress, verify attempts, gate and review results, the session's transcript path.
- D3: A blocked task is derived from the plan log (`B:` without a later `U:`), so losing `.dflow/` loses no decision.
- D4: Review findings are written by the reviewer through `dflow review add`, not returned as prose. A finding's evidence command exits non-zero while the defect exists, so re-running it both proves the finding and confirms the fix.
- D5: Worker worktrees are created by the CLI from the current head; a worker's commits come back with `git cherry-pick -n`, so `dflow done` makes the same single commit as inline work.
- D6: darkmem is reached over REST with `fetch`; the URL and key variable live in `~/.dflow/config.json`, the project name in `docs/dflow/config.json`. Every darkmem step is a no-op when either is missing.
- D7: The mod reads `.dflow/hud.json`, which the CLI rewrites on every state change, so the mod parses no Markdown.
- Interfaces: plan grammar, board grammar and the state file are specified in `plugins/dflow/README.md`.
- Out of scope: Codex support; running the paid comparison against dforge (the tooling is built, the run is the owner's call).
